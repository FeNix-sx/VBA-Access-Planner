# Техническое задание: модуль «Дни рождения»

**Приложение:** подвижной дневник / планировщик (MS Access, VBA).  
**Главная форма:** `f_daily_planner` (заголовок окна: «ПЛАНИРОВЩИК»).  
**Версия документа:** 1.0  
**Статус:** к реализации; настоящий документ описывает требования и чек-лист, без выполнения работ в коде.

---

## 1. Схема текущего макета главной формы (по референс-скриншоту)

Ниже — логическая схема расположения зон **до** внедрения панели ДР. Используется для понимания, **куда** встраивается новый столбец (справа от календаря, с расширением ширины формы при включении настройки).

### 1.1. Блок-схема (сверху вниз)

```text
+------------------------------------------------------------------+
|  Заголовок окна: ПЛАНИРОВЩИК                                      |
+------------------------------------------------------------------+
|  [Добавить исполнителя]  [ФИЛЬТР ПО ИСПОЛНИТЕЛЮ ▼]  [Поиск       |
|                           событий]  [Добавить событие]            |
|              [ ] Скрывать выполненные события                     |
+------------------------------------------------------------------+
|  [Предыдущий месяц]     Март 2026 (текущий месяц)  [Следующий     |
|                                                         месяц]    |
+------------------------------------------------------------------+
|  Пн | Вт | Ср | Чт | Пт | Сб | Вс                                   |
|-----+----+----+----+----+----+----                                  |
|     |    |    |    |    |    |    <- сетка 7 x 6 (дни + хвосты     |
|     |    |    |    |    |    |       прошлого/следующего месяца)   |
|     |    |    |    |    |    |    (будни / выходные — разное       |
|     |    |    |    |    |    |     оформление ячеек)                |
+------------------------------------------------------------------+
|  [Демонстрационный режим]  [Сменить оформление]  [Закрыть          |
|                                                    ежедневник]    |
|                                      версия 26.02.26 (справа внизу)|
+------------------------------------------------------------------+
```

### 1.2. Назначение зон (кратко)

| Зона | Содержимое |
|------|------------|
| Верх, ряд 1 | Кнопки: исполнитель, комбофильтр, поиск событий, добавить событие |
| Верх, ряд 2 | Флажок «Скрывать выполненные события» |
| Навигация месяца | Предыдущий месяц / подпись месяца / следующий месяц |
| Центр | Календарная сетка (7 дней недели × 6 строк), номер дня в ячейке |
| Низ | Деморежим, смена оформления, закрыть; подпись версии |

### 1.3. Место внедрения панели «Дни рождения» (целевое)

- **Не** внутри ячеек календаря.
- Отдельная **вертикальная колонка справа** от блока сетки (или согласованная сторона), появляющаяся при включённой настройке «Показать дни рождения».
- Ширина главной формы **увеличивается** при показе колонки, чтобы календарь и колонка ДР не перекрывались.

Референсный скриншот может храниться отдельно (например в каталоге проекта); при обновлении UI схему в п. 1.1–1.2 следует синхронизировать.

## 2. Назначение и цели модуля

### 2.1. Назначение

Вести **отдельно** от событий календаря справочник **дней рождения** (люди/сотрудники) и показывать на главном экране **ближайшие** ДР в отдельной колонке.

### 2.2. Цели

- ДР **не** являются записями в модели обычных событий (`tbEventInstances` и аналоги).
- Отображение ДР **не** размещается в ячейках календарной сетки.
- Ввод/редактирование — **отдельная** форма (не форма генератора обычных событий).
- Видимость панели ДР **запоминается** между сеансами (как прочие настройки, через `tbSettings`).

---

## 3. Термины

- **Окно просмотра** — интервал календарных дат **[Сегодня − N … Сегодня + M]**, где **N**, **M** — целые неотрицательные константы в VBA (стартовые значения, например **N = 10**, **M = 10**). **Сегодня** = системная **`Date()`** на момент обновления (загрузка формы, `Requery` после правок и т.д.).
- **Дата ДР в году** — день и месяц из даты рождения, перенесённые на год расчёта окна (с учётом перехода через 31.12 / 01.01).
- **v1** — объём без привязки записей к учётной записи пользователя (см. раздел 12).

---

## 4. Требования к данным

### 4.1. Таблица в BE

Таблица, например **`tbBirthdays`**, во внешней БД; подключение к FE — по тому же принципу, что и остальные таблицы (`tbTableConnections` / существующие процедуры).

### 4.2. Поля (минимум)

| Поле | Тип | Обяз. | Описание |
|------|-----|-------|----------|
| PK | AutoNumber / Long | да | Уникальный ключ |
| Фамилия | Текст | да | |
| Имя | Текст | да | |
| Отчество | Текст | нет | |
| ДатаРождения | Date | да | Полная дата (для возраста и високосных лет) |
| Примечание | Текст | нет | |

Импорт из файлов **не** предусмотрен.

---

## 5. Логика отбора и сортировки

1. В окно попадают записи, у которых **дата ДР в году** (с корректным переходом года) лежит в **[Сегодня − N … Сегодня + M]**.
2. **Группировка** для отображения — по календарной дате наступления ДР в окне.
3. **Внутри одной даты** сортировка: **Фамилия → Имя → Отчество** (лексикографически, кириллица).

---

## 6. Формулировки про возраст

Обязательно для каждой строки человека:

- дата группы **= Сегодня** — «исполняется …» / формулировка про **юбилей** (25, 30, 40 …) по согласованному в коде правилу;
- дата группы **< Сегодня** (в окне) — «исполнилось … лет»;
- дата группы **> Сегодня** — «исполнится … лет».

Возраст считается от полной даты рождения до соответствующей даты в году отображения.

---

## 7. Отображение: объект «Отчёт» Access

1. Реализация панели — **отчёт** (например `rptBirthdays`), встроенный в `f_daily_planner` через **подчинённый отчёт**.
2. Макет: один столбец, заголовок колонки («Дни рождения» / «Отмечают дни рождения»); в колонке не дублировать в каждой строке слово «день рождения» избыточно.
3. **Строка с датой выводится только если** в этот календарный день в окне есть **хотя бы один** ДР (в отличие от календаря, где ячейка дня всегда видна).
4. Несколько человек в один день — несколько строк в группе, порядок по п. 5.
5. **Обновление:** минимум `Requery` при загрузке главной формы, после сохранения записи ДР, при первом показе панели. Таймер через полночь — опционально для v1.

---

## 8. Настройки главной формы

1. Ключ в **`tbSettings`**, например `ShowBirthdaysPanel` (значения в формате проекта).
2. По умолчанию после внедрения: панель **скрыта** (первый запуск).
3. Элемент «Показать / скрыть дни рождения»; при показе — **увеличение ширины** формы под колонку.
4. Состояние восстанавливается при следующем открытии.

---

## 9. Формы ввода

1. Отдельная форма добавления/редактирования: Фамилия, Имя, Отчество, Дата рождения, Примечание (опц.).
2. Желательно v1: список всех записей + удаление с подтверждением.
3. Кнопка вызова с главной формы (например в верхней панели рядом с существующими действиями — точное место согласовать с макетом).

## 11. Критерии приёмки (v1)

- [ ] Таблица `tbBirthdays` в BE, связь с FE.
- [ ] CRUD через согласованные формы.
- [ ] Подчинённый отчёт на `f_daily_planner` при включённой настройке; источник с окном **[Сегодня−N … Сегодня+M]**.
- [ ] Нет строк в отчёте для дат без ДР в окне; группировка по дате; сортировка ФИО внутри дня.
- [ ] Корректные формулировки «исполняется / исполнилось / исполнится» и возраст/юбилей.
- [ ] Настройка видимости сохраняется в `tbSettings`.
- [ ] ДР не отображаются в ячейках сетки и не дублируются как обычные события.

---

## 12. Вне объёма v1

- Поле владельца / фильтр по пользователю (локальная сеть, 5–10 пользователей) — **не реализуется**; при появлении логина — отдельная итерация (поле + фильтр в запросе).
- Импорт, push-уведомления, смена N/M через UI (достаточно констант в коде).
